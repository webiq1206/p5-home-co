# Estimator exit callback offer

The shared estimator offers “Prefer to talk about your project? Call us, or leave your number and we’ll call you.” Call us opens the brand phone link; Request a callback collects only a US phone number with explicit project callback intent, separate from marketing consent.

The estimator Exit and ordinary same-origin navigation links show the offer once per browser tab session, including untouched forms. Continue form, Escape and backdrop dismiss it without losing work; Leave without finishing performs the original navigation/collapse. Ordinary internal step Back remains a step change. A desktop pointer leaving the top edge can show it only after meaningful input and at least twenty seconds. Coarse pointers, completed/read-only views, inactive embedded forms and ongoing operations do not trigger that automatic offer. A repeated exit is never intercepted. Browser Back, refresh and tab/app closure are not trapped. Native browser unload dialogs cannot contain a custom offer and mobile closure events are unreliable.

Callback submissions reuse /api/recovery/callback and estimator_sessions, keyed by the draft UUID. They do not submit the quote, create a second project, upload files, mutate the draft or enroll marketing. Staff receive the brand’s existing callback email with a draft reference, revision and service; scope text, files and other contact fields are not copied into the callback. The first requested number is immutable for this flow and concurrent retries share the existing notification claim. Invalid numbers and absent explicit callback consent are rejected. A stored request is distinguished from an unconfirmed staff notification. No callback time is promised. The endpoint does not send customer SMS or place calls.

Qualification uses a loopback server with all APIs mocked plus an isolated PostgreSQL-compatible database and captured mailer. It checks mobile/desktop layouts, keyboard focus, cancellation, repeat exit, reload, selected-file retention and callback failure/retry. No real callback request is needed for live visual verification. Before any future live callback test, agree a controlled recipient/number and tell the receiving staff not to place a real call; any automated call/SMS would require separate explicit authorization. Existing production settings and schema deferrals remain unchanged.

Browser limitations: https://developer.mozilla.org/en-US/docs/Web/API/Window/beforeunload_event and https://developer.mozilla.org/en-US/docs/Web/API/Document/visibilitychange_event

## Explicit contact entry — October 13

A prominent “Just contact me” button opens the same phone-only callback form before any project description or questions. Explicit requests remain available after a previous dismissal and in a collapsed embedded estimator. Opening, canceling and submitting the callback preserve the existing project. The phone field receives focus, Escape restores focus to the shortcut, and uncertain retries reuse the same frozen request. Automatic exit offers retain their once-per-session behavior. No new endpoint, provider, marketing consent or customer call/SMS is introduced.
