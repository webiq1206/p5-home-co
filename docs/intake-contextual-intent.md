# Contextual intake and routing

A typed request to “build a modern farmhouse 3200 ft.²” previously failed the new-home evidence guard because it accepted house/home but not farmhouse. Unknown service also routed every specialty site to P5. Manual review intentionally skipped the AI reader, leaving a clear typed request unclassified.

The draft save and scope reconciliation now retain a conservative interpretation of explicit authored text. It handles the verified phrase matrix, common typos, negation, whole-project context and later explicit corrections. Source-derived facts carry the original evidence and are invalidated when the source changes. Independent customer choices remain authoritative; a contradictory description creates one project-type clarification rather than silently changing the choice or initiating a transfer. Unknown projects remain with the current site. P5 keeps every discipline in one intake, and cabinet repair overlap stays with Cabinet.

This bounded fallback is not a general language model or a document reader. Ambiguity stays unknown. It does not infer price, unspecified dimensions, land ownership, file findings, service eligibility or an AI success. A failed reader retains its warning and does not gain a successful reading fingerprint. The existing AI prompt also requests contextual classification; no new provider spending is added.

Validation: phrase/evidence/routing matrix; real draft endpoint with disposable PGlite and zero network; correction and explicit-choice persistence; unread original preservation; successful versus failed reader reconciliation; mobile manual-review UI with mocked APIs; existing intake, handoff and question-memory regressions. No live customer form or callback is submitted by these tests.
