# Estimator response time and interface repair

The reported four-page Construction scope stalled on its last page. Production inspection found 4 minutes 13 seconds total, two invalid provider outputs, and only three pages read.

This release shares a 54-second server budget across background stages and provider retries, with a 58-second browser deadline covering save, upload and processing waits. A timeout restores the editable project and preserves completed work. It never makes an incomplete estimate publishable. A completed, accurate price within 60 seconds for every possible file, connection and provider condition is not guaranteed by a timeout.

Ordinary PDF pages are grouped in sets of four without dropping original page identities. Large drawings keep the existing detailed rendering and full coverage checks. The interactive fallback uses the configured fast model or Sonnet; strict local evidence validation remains mandatory. A known formatting wrapper is normalized before validation. Blank structured facts are rejected by the provider schema.

Pricing stages reuse saved replies without stopping after each new response. Clean, fully reviewed document inventories can reuse their source-linked work items. Text additions, revisions, alternates and aggregate records retain the full inventory step. Mapping batches now contain up to twelve items, with the original independent coverage audit still required. Financial formulas, approved rates and customer contact requirements are preserved. Email and CRM delivery run after the response through Next.js after and the durable outbox.

The interface uses a light workspace, clearer hierarchy, one project input and upload control, one visible clarification, selectable answers, compact inline progress and the existing final mobile estimate action. Ordinary Continue controls remain in the page.

Local verification: all five TypeScript checks, scope/provider/pricing regression suites, original page coverage and resume checks, blocked provider/response-body deadlines, and mobile entry/question/review/progress fixtures. Each brand's browser fixture simulates a stalled request and confirms recovery before 60 seconds with the typed scope retained. Live provider timing and deployment verification must be recorded separately; synthetic tests are not live latency evidence.
